## Безопасное включение

**По умолчанию сохраняется исходный путь NetworkX, включая разрешение равных
путей, обычный расчёт метрик, геометрические операции и копирование зон.**
Установка SciPy сама по себе не включает ускорение.

```python
from genesis.backends import get_backend, use_backend

assert get_backend() == "networkx"
result = algorithm(env=G, ...)  # прежний путь без изменения вызовов

with use_backend("scipy"):
    result_fast = algorithm(env=G, ...)  # явное включение всего вычислительного слоя

assert get_backend() == "networkx"
```

`...` здесь обозначает обычные аргументы выбранного алгоритма.
Контексты можно вкладывать, в том числе временно возвращаться к `networkx`
внутри блока `scipy`. После выхода или исключения предыдущий режим
восстанавливается. Неизвестное имя вызывает `ValueError` до изменения режима.

Режим хранится в `ContextVar`, а не в общем изменяемом флаге. Обычные новые
потоки начинают с NetworkX; asyncio-задачи наследуют контекст при создании,
`asyncio.to_thread` явно переносит его в поток. Раздельный выбор режима
**не означает потокобезопасность общего кэша движка**. Режим не хранится в
объекте алгоритма: существующий объект использует контекст текущего вызова.

SciPy — дополнительная зависимость:

```bash
# После публикации релиза с extra fast:
python -m pip install 'genesis-spatial-opt[fast]'
# Для проверки этого PR — из локального исходного дерева:
python -m pip install -e './work/genesis[fast]'
```

Для расчёта в режиме NetworkX SciPy не требуется самому Genesis. Другие
зависимости могут устанавливать или импортировать SciPy для собственных функций.
При входе в `use_backend("scipy")` зависимость проверяется до начала расчёта.
Если её нет, возникает `ModuleNotFoundError` с командой установки, а режим не
меняется. Прямой импорт низкоуровневого `genesis.engine` требует SciPy.

Пользовательские алгоритмы состояния, callable-веса и неподдерживаемые метрики
сохраняют исходный путь. В частности, пользовательский подкласс метрики не
обрабатывается через унаследованный `_native` в обход собственного `__call__`.

## Состав

- `genesis/backends.py`: контекст выбора режима и ленивая загрузка движка.
- `genesis/engine.py`: индекс графа, Дейкстра SciPy, кэш строк расстояний,
  разреженные пакеты для `get_atm`, кэш геометрии.
- Подключение в `genesis/states.py`, `genesis/metrics.py`, `genesis/mclp.py`,
  `genesis/best_points.py`, `fire_units/mclp.py`, `fire_units/metrics.py`.
- Сброс уже существующего кэша после `graphs.speeds.set_graph_travel_times`,
  даже если скорость меняется за пределами ускоренного контекста.
- Дополнительная зависимость `[fast]`, тесты, CI в двух режимах, бенчмарк.

Каталога `genesis.fast`, `MatrixState`, точных решателей, гибридов, собственного
VNS, контракта API и демо в этой ветке нет. Существующий авторский
`ArrivalTimeMatrixState` не удаляется: это часть исходного Genesis.
Смысл метрик, включая исходный знаменатель индекса прикрытия, не меняется.

### Бенчмарк: 130 сценариев

Эталон — свежий прогон самого коммита первого PR `0561296` в отдельной
рабочей копии в том же окружении (227,86 с).
Режим по умолчанию запущен **без аргумента выбора backend**.

| Версия | same | quality | worse | Ошибок | Время сценариев |
|---|---:|---:|---:|---:|---:|
| Новый код, NetworkX по умолчанию | **130** | **0** | **0** | **0** | 229,61 с |
| Новый код, явный SciPy | 109 | 17 | 4 | 0 | 4,37 с |

Помимо компаратора, для режима по умолчанию проверено **точное равенство
содержимого всех 130 JSON-результатов** эталону (без времени выполнения и meta).
В ускоренном режиме все 130 JSON-результатов точно равны результатам исходной
ветки `pr/transparent-fast-engine` до смены базы. Перенос на первый PR не
устранил и не скрыл известные расхождения.

Для SciPy: Сосновоборск — 65/65 `same`; сетка — 44 `same`, 17 `quality`, 4 `worse`.
`same` — статус компаратора с числовым допуском, не обязательно побитовое равенство.
Для стохастических методов сравниваются запуски с seed 0–4. `quality` может
означать другую расстановку с тем же значением, не обязательно улучшение.

На сетке ускоренный режим хуже эталона:

| Сценарий | База | SciPy |
|---|---:|---:|
| `grid/multi/LSCPCommon_Far/mean` | 4,5625 | 4,625 |
| `grid/multi/LSCPCommon_Genesis/max` | 7 | 9 |
| `grid/multi/LSCPCommon_Genesis/cover6` | 78,125 | 73,4375 |
| `grid/multi/Hybridization/cover6` (среднее / худшее) | 57,8125 / 57,8125 | 56,875 / 54,6875 |

Разрешение равных кратчайших путей и выбор ближайшего подразделения у NetworkX
и SciPy могут отличаться. На сетке это меняет зоны обслуживания и дальнейшую
траекторию эвристик. Такие равенства возможны и на реальных данных.
**Ускоренный режим не гарантирует эквивалентность на любых графах.**
Существующие вызовы защищены тем, что этот режим не включён по умолчанию.
Совпадение 130 сценариев также не доказывает совместимость всех возможных вызовов.

Отношение времён база/SciPy данного прогона — около ×52,1 (NetworkX/SciPy — ×52,5).
Один прогон не устанавливает универсальное ускорение. Ранний серверный замер
`get_atm` здесь заново не выполнялся и как новый результат не заявляется.

## Ограничения кэша ускорителя

При ручном изменении весов или координат графа вызовите
`genesis.backends.clear_cache(G)`. Это не требует установки SciPy и сбрасывает
уже загруженный кэш, если он есть. Вход/выход из контекста сам по себе кэш не очищает.
Автопроверка количества узлов/рёбер не обнаруживает все изменения содержимого
графа. При изменении родительского графа сбрасывайте также кэши уже используемых
подграфов. Маски `area` и таблицы данных метрик не следует изменять на месте
между ускоренными вызовами: создавайте новые маски/объекты метрик.
`get_atm` по-прежнему возвращает плотный DataFrame: разреженная промежуточная
обработка не устраняет стоимость хранения самого результата.
